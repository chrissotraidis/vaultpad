# Report 1: Build System, iOS Platform Layer, CI, Release Pipeline

Repo audited: local clone (HEAD = `e97087b9582f37075db347a89898887320753f8b`, "Remove pause window", 2025-02-16 — verified identical to upstream `alexbatalov/fallout2-ce` `main` HEAD via GitHub API). All web/GitHub data accessed **2026-07-17**.

## Key facts (TL;DR)

- **iOS is a first-class, working target** built via plain CMake + Xcode generator. No committed `.xcodeproj`; the project is generated by `cmake --preset ios`.
- **Presets**: `CMakePresets.json` (schema **version 6**, i.e. requires CMake ≥ 3.25 to parse, despite declaring `cmakeMinimumRequired` 3.19) defines `ios` configure preset (Xcode generator, `CMAKE_SYSTEM_NAME=iOS`, empty code-sign identity) and `ios-debug`/`ios-release` build presets.
- **Deployment target iOS 12.0, arm64 only, device SDK only** — no simulator preset, no x86_64/simulator-arm64 configuration.
- **The old `leetal/ios-cmake` toolchain file was deleted** from the repo on 2025-02-09 (commit `593f801`, "Add cmake presets (#452)"); `release.yml` still references it, so **the release pipeline's iOS job is broken on main today** (dead toolchain path + retired `macos-12` runner).
- **CI (`ci-build.yml`) pins `runs-on: macos-13`, which GitHub retired in December 2025** — the iOS CI job cannot run on upstream main as-committed. The only green 2026 run (2026-01-18, all jobs incl. iOS **success**) executed a fork-modified workflow using `macos-14`.
- **Dependencies are 100% auto-fetched at configure time via `FetchContent`**: SDL `release-2.26.1`, zlib `v1.3.1`, fpattern `8523173` (v1.9, alexbatalov fork). Nothing to install manually except CMake+Xcode; network access required at configure.
- **The shipped v1.3.0 IPA is completely unsigned** (`codesign: "code object is not signed at all"`, no `_CodeSignature`, no `embedded.mobileprovision`), arm64-only, `MinimumOSVersion` **11.0**, bundle id `com.alexbatalov.fallout2-ce`, built with Xcode 14.2 / iOS 16.2 SDK on macOS 12. 5,717 downloads. It is a plain CPack ZIP of `Payload/fallout2-ce.app` renamed `.ipa` — sideload-only (AltStore/Sideloadly).
- **Repo activity has collapsed**: last commit 2025-02-16; commits/year: 2022: 591, 2023: 209, 2024: 20, 2025: 59, 2026: 0. Last release v1.3.0 (2024-04-21). 135 open issues, 2,363 stars.
- **iOS platform layer is tiny**: one `.mm` file (Documents-dir path), a shared touch-gesture translator (`src/touch.cc`), `os/ios/` holds only Info.plist + LaunchScreen.storyboard + a single 1024×1024 icon.

### `CMakePresets.json`

- Schema `"version": 6` with `cmakeMinimumRequired: 3.19.0` (`CMakePresets.json:2-7`). Presets file **format v6 itself requires CMake ≥ 3.25**.
- `darwin-base` (hidden, `CMakePresets.json:107-121`): **generator `Xcode`**, cache var `CMAKE_XCODE_ATTRIBUTE_CODE_SIGN_IDENTITY: ""` (empty string → ad-hoc/no identity), condition `hostSystemName == Darwin`.
- `ios` configure preset (`CMakePresets.json:129-136`): inherits `darwin-base`, adds `CMAKE_SYSTEM_NAME: "iOS"`. **No toolchain file** — relies on CMake's built-in iOS cross-compilation. Binary dir: `${sourceDir}/out/build/ios`.
- Build presets `ios-debug` (configuration `Debug`) and `ios-release` (configuration `RelWithDebInfo`) (`CMakePresets.json:186-194`).
- Other presets: `windows-x86`/`windows-x64` (VS 2019), `linux-x86/x64` debug/release (`FALLOUT_VENDORED: OFF`), `macos`.

**Code signing**: only mechanism is `CMAKE_XCODE_ATTRIBUTE_CODE_SIGN_IDENTITY=""`. There is **no** `CODE_SIGNING_ALLOWED`, `CODE_SIGNING_REQUIRED`, `DEVELOPMENT_TEAM`, or provisioning-profile setting anywhere in the repo (verified by grep). CMake's Xcode generator defaults `CODE_SIGNING_ALLOWED=NO` for iOS when no identity is set.

**Simulator support: none.** No simulator preset; `CMAKE_OSX_ARCHITECTURES` cached to `arm64`; `CMAKE_OSX_SYSROOT` never set to `iphonesimulator`. The old (deleted) leetal toolchain supported `SIMULATOR64`/`SIMULATORARM64` but the current preset flow does not.

### iOS-specific source layer

- `src/platform/ios/paths.mm` — the only Objective-C++ file: `iOSGetDocumentsPath()` returns the sandbox `Documents/` dir (modelled after `SDL_AndroidGetExternalStoragePath`).
- `src/win32.cc:39-43` — despite the filename, this is the cross-platform `main()`:

```c
#if __APPLE__ && TARGET_OS_IOS
    SDL_SetHint(SDL_HINT_MOUSE_TOUCH_EVENTS, "0");
    SDL_SetHint(SDL_HINT_TOUCH_MOUSE_EVENTS, "0");
    chdir(iOSGetDocumentsPath());
#endif
```

  The game simply `chdir`s into Documents and expects `master.dat`, `critter.dat`, `patch000.dat`, `data/` there (user copies them via File Sharing).
- `src/touch.cc` / `src/touch.h` — shared (iOS+Android) SDL touch-gesture recognizer (tap / long-press / pan, 1-2 fingers → mouse emulation), last touched 2023-05-09 (`a06097a`, "Improve touch controls (#283)").

## 2. Dependencies

All vendored dependencies are **FetchContent stubs** (only a `CMakeLists.txt` + LICENSE in-tree; sources downloaded from GitHub at configure time). No submodules, no bundled source.

- `third_party/sdl2/CMakeLists.txt`: FetchContent of `https://github.com/libsdl-org/SDL` tag `release-2.26.1`, GIT_SHALLOW. Built as **static lib** (`SDL_SHARED OFF`, `SDL_STATIC ON`, `SDL_LIBC ON`); links `SDL2-static` + `SDL2::SDL2main`. → **SDL 2.26.1** (Nov 2022; SDL2, not SDL3).
- `third_party/zlib/CMakeLists.txt`: FetchContent of `https://github.com/madler/zlib` tag **`v1.3.1`**, links `zlibstatic`.
- `third_party/fpattern/CMakeLists.txt`: FetchContent of `https://github.com/alexbatalov/fpattern` pinned commit `8523173ec252c3b796fcdfca0fcc6329642fbbe3` (# v1.9).
- No other third-party libs — audio/movie decoders (ACM in `src/sound_decoder.cc`, MVE in `src/movie_lib.cc`) are re-implemented in-tree.
- `FALLOUT_VENDORED=ON` default (`CMakeLists.txt:23,364-370`); `OFF` switches to `find_package`. On iOS the vendored path is the only sensible one; configure requires internet + git.

## 3. Exact iOS build commands on macOS today

README (`README.md:75-83`) documents **no build commands** for iOS — only sideloading of the released IPA via AltStore/Sideloadly, plus: "Alternatively you can always build from source with your own signing certificate" (no instructions how). No BUILD.md. De-facto documentation is CI. Reconstructed from `CMakePresets.json` + `.github/workflows/ci-build.yml:105-116`:

**(a) Generate the Xcode project** (requires macOS, Xcode + CLT, CMake ≥ 3.25, network):

```console
$ git clone https://github.com/alexbatalov/fallout2-ce
$ cd fallout2-ce
$ cmake --preset ios
```

→ produces `out/build/ios/fallout2-ce.xcodeproj` (open-able in Xcode; unsigned by default).

**(b) Device build (unsigned, arm64, iphoneos SDK):**

```console
$ cmake --build --preset ios-debug          # Debug
$ cmake --build --preset ios-release        # RelWithDebInfo
```

→ `out/build/ios/Debug-iphoneos/fallout2-ce.app` (resp. `RelWithDebInfo-iphoneos`). To install on a real device: open generated project in Xcode, set Development Team/signing identity, Run — or re-configure with `-DCMAKE_XCODE_ATTRIBUTE_DEVELOPMENT_TEAM=XXXXXXXXXX -DCMAKE_XCODE_ATTRIBUTE_CODE_SIGN_IDENTITY="Apple Development"`.

**(c) Unsigned IPA (exactly what CI ships):**

```console
$ cd out/build/ios
$ cpack -C Debug            # or: cpack -C RelWithDebInfo
```

→ `out/build/ios/fallout2-ce.ipa` — CPack ZIP containing `Payload/fallout2-ce.app` renamed `.ipa`.

The **release** pipeline (v1.3.0-era, `.github/workflows/release.yml:74-96`) used a now-broken invocation:

```console
cmake -B build -D CMAKE_TOOLCHAIN_FILE=cmake/toolchain/ios.toolchain.cmake \
      -D ENABLE_BITCODE=0 -D PLATFORM=OS64 -G Xcode \
      -D CMAKE_XCODE_ATTRIBUTE_CODE_SIGN_IDENTITY=''
cmake --build build --config RelWithDebInfo -j $(sysctl -n hw.physicalcpu)
cd build && cpack -C RelWithDebInfo
```

`cmake/toolchain/ios.toolchain.cmake` **no longer exists on main** (deleted 2025-02-09), so this fails at configure on current sources.
