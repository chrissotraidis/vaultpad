# iPad Simulator baseline playtest

Date: 2026-07-18

Build: active engine `d8d99fe9`, VaultPad product configuration

Device: iPad Pro 11-inch (M4) Simulator, iOS 18.5

Input: simulated touch plus Simulator keyboard

## Proven

- The active engine configures and compiles for arm64 iOS Simulator under Xcode 26.6.
- The app installs and launches with the neutral visible name **VaultPad** and bundle id `com.chrissotraidis.vaultpad`.
- With no game data, the current engine reaches its expected missing-`master.dat` alert.
- With the user-supplied `master.dat`, `critter.dat`, `patch000.dat`, `data/`, and generated `ce.dat` copied only into the private Simulator container, the game boots through the intro and reaches the main menu.
- A premade character can start a new game and reach the Temple of Trials.
- Keyboard input reaches the engine in Simulator (Escape and menu accelerators verified).
- A one-finger pan moves the gameplay cursor, and the player can be issued a movement command.

## Baseline touch defects

### P0 — touch coordinates land above the finger

On the 11-inch simulator at the engine's default 640×480 logical resolution, tapping the visible **Done** row in the in-game options menu activated **Exit Game**, one row above. The engine cursor also rendered above the requested tap position. This reproduces the PRD's letterbox/logical-coordinate mismatch and is dangerous because a benign menu action can become destructive.

### P0 — taps do not complete reliably

On the main menu and character selector, a tap moved the engine cursor and depressed the intended button but did not consistently deliver the release/action. A later pan caused the pending action to complete. Touch-down/release sequencing must be made deterministic before deeper playtesting.

### P1 — gameplay defaults to virtual trackpad

The world view still forces relative trackpad behavior. It works, but requires a pan to position the cursor and a separate tap to act. Hybrid/direct behavior remains the intended default, with classic trackpad retained as a setting.

### P1 — no native first-run path

The missing-data alert is engine text, not VaultPad onboarding. Data still had to be copied into the app container manually for this baseline.

## Next loop

1. Correct touch-to-logical coordinate conversion using SDL's viewport/logical transform.
2. Replace the LIFO gesture stack with FIFO ordering and make tap down/up delivery explicit.
3. Add a persistent touch-mode setting and allow direct world-view touch.
4. Repeat main menu, character selection, options, world movement, combat, and save/load touch tests before building the native importer around an unstable input layer.

## Scope note

This is Simulator evidence only. Physical-device gestures, Magic Keyboard trackpad, Bluetooth mouse, Apple Pencil, battery, thermal behavior, and hardware interruptions are not yet certified.
